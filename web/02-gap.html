2. gap 與 safe-area

這一頁最重要。前三項都是「方塊之間有沒有間距」，寫法不同、支援門檻也不同 —— 請特別注意哪一項有間距、哪一項沒有。

Ch 57grid-gap（舊語法） 主專案目前 0 處，但這是救援方案

測試：grid + grid-gap
參考：float + margin

左右兩邊方塊之間的空隙一樣寬嗎？
✓ 一樣（都有明顯空隙）= 支援
✗ 左邊方塊黏在一起 = 不支援

Ch 66gap 用在 grid 主專案用了 36 處

測試：grid + gap
參考：float + margin

左右兩邊方塊之間的空隙一樣寬嗎？
✓ 一樣 = 支援
✗ 左邊方塊黏在一起 = 不支援

Ch 84gap 用在 flex 主專案用了 319 處，最大宗

注意：這一項的「引擎宣稱」會騙人。 @supports 只能整體偵測 gap 這個屬性，分不出 flex 還是 grid。 Chromium 66~83 認得 gap（grid 上有效），所以會回報「支援」，但 flex 容器上完全不生效。 這一項只看下面左右並排的結果。

測試：flex + gap
參考：flex + margin

左右兩邊方塊之間的空隙一樣寬嗎？
✓ 一樣 = 支援
✗ 左邊三個方塊完全黏在一起 = 不支援

Ch 69env(safe-area-inset-*) 主專案用了 209 處

測試：用 env()
參考：不留白

左右兩個藍色方塊，在淺藍底色裡的位置一樣嗎？
✓ 兩邊方塊都貼著左邊 = 支援
✗ 左邊方塊被推到右邊去了 = 不支援
（這一項也請看上面那行實測數值，比看圖更準）

關鍵calc() 裡混 env() 主專案用了 10 處，是最致命的寫法

這一項測的不是某個特性，而是失敗方式。calc() 裡只要有一個看不懂的東西， 整條規則會被整個丟掉，不是退化成一半正確。主專案寫的 height: calc(100dvh - env(...)) 就是這種寫法 —— 高度會直接消失，整個版面塌掉。

測試：calc(80px + env())
參考：寫死 80px

左右兩個藍色長條一樣高嗎？
✓ 一樣高 = 支援
✗ 左邊完全不見了（高度變成 0）= 不支援
